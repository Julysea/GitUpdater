GitUpdater 使用帮助

快速开始 设置项 资源文件名 释放路径 压缩包处理 版本判断 命令行参数 配置文件 常见问题

1. 快速开始

  1. 把 GitUpdater.exe 放到要更新的程序目录。
  2. 运行 GitUpdater.exe，第一次运行会显示设置窗口。
  3. 填写 GitHub 仓库 和 资源文件，点“确定”。
  4. 发现新版本时弹出确认窗口，点“是”开始下载与解压；点“否”或关闭窗口则不更新。
  5. 更新完成后窗口显示“更新完成”，点“关闭”退出。
GitUpdater 只负责更新，不会启动被更新的程序。更新前请先关闭该程序，否则文件被占用会失败。

2. 设置项说明

项目说明
GitHub 仓库必填。仓库地址，例如 https://github.com/anomalyco/opencode。程序读取该仓库 Releases 列表的第一条（与 GitHub 页面顺序一致）。
资源文件必填。Release 中要下载的资源文件名，必须与发布页上的文件名一致（不区分大小写）。支持版本占位符，见 第 3 节。
更新是：发现新版本直接更新；询问：先弹出确认窗口（默认）；否：不检查、不更新，直接退出。
每天只检查一次更新勾选后，同一天内重复运行会直接退出，避免频繁请求 GitHub。
解压后删除下载的压缩包压缩包解压成功后删除下载的文件；只下载模式（非压缩包格式）会保留文件。
自动去掉压缩包的单层根目录压缩包内只有一个顶层文件夹时，把该文件夹里的内容直接放到安装目录，而不是多套一层目录。
指定释放内容路径只提取压缩包里某个子目录的内容，留空表示全部提取。见 第 4 节。
日志文件日志路径，默认 gitupdater.log（相对 exe 所在目录）。留空则关闭日志。
本窗口左下角的“帮助”按钮会用默认浏览器打开本页。帮助页已内嵌在 GitUpdater.exe 中（中文、英文各一份，按系统界面语言自动选择），首次点击时释放到系统临时目录，不会在程序目录生成任何文件。若在 exe 旁放置 help_zh.html / help_en.html，则优先打开对应语言的外部文件，便于自定义。

3. 资源文件名与版本占位符

资源文件不是正则表达式，也不是通配符，只支持两个占位符：

占位符含义示例（最新 tag 为 v0.24.0-rc.1）
[$ver]tag 去掉开头的 vmarktext-win-x64-[$ver].zip → marktext-win-x64-0.24.0-rc.1.zip
[$tag]完整 tagmyapp-[$tag].zip → myapp-v0.24.0-rc.1.zip
若实际文件名中包含 v（例如 TriliumNotes-v0.107.0-windows-x64.zip），要写成 TriliumNotes-v[$ver]-windows-x64.zip，否则替换结果缺少 v，会导致匹配失败。

如果找不到完全一致的资源名：

  • 会尝试找名字最接近的同类文件（扩展名需相同），并弹窗让你确认是否下载；
  • 差距过大时，直接列出全部可用资源并报错退出。

确认/无更新窗口中都可以点“重新定义配置”回到设置窗口：点“确定”保存后立即重新检查，“取消”则回到原窗口。

4. 指定释放内容路径（BinPath）

填写压缩包内相对于压缩包根目录的子目录，例如 HydraPortable/App/Hydra，表示只提取该目录下的内容。

  • 分隔符 / 和 \ 都可以；首尾斜杠会被忽略，HydraPortable\App\Hydra\ 等同于 HydraPortable/App/Hydra。
  • 大小写不敏感。
  • 留空 = 提取全部内容。
  • 该路径是压缩包内部的路径，不是本机磁盘路径。
找不到配置的路径时，程序会在日志中记录 [WARN] Configured path not found in archive: ... (extracting all)，然后按“全部提取”处理。此时先确认包内是否还有一层顶层目录（例如实际是 app-1.0/HydraPortable/App/Hydra），正确写法要带上这一层。

5. 支持的压缩包格式

格式处理方式
.zip用 PowerShell Expand-Archive 解压
.7z / .rar调用 7-Zip；找不到 7-Zip 时尝试 Windows 自带 tar，仍失败则报错
.tar / .tar.gz / .tgz / .tar.bz2 / .tbz2 / .tar.xz / .txz用 Windows 自带 tar 解压
其他格式（.exe、.msi 等）只下载，不解压、不运行

解压过程使用临时目录 <安装目录>.gitupdater_tmp，完成后删除。安装后还会清理名字形如版本号的旧版本目录（例如 156.0.8078），当前版本目录保留。

6. 版本判断

不解析语义版本，只比较最新 tag 字符串：与上次记录相同则跳过（显示“当前已是最新版本”），不同则更新。该记录同时绑定仓库名，换仓库后会重新检查。

使用 --force 可以忽略相同 tag 的判断，强制重新下载。

7. 命令行参数

参数说明
--settings打开设置窗口；点“确定”保存后退出，点“取消”不保存并退出
--force忽略“每天只检查一次”和相同 tag 判断，直接更新
GitUpdater.exe --settings
GitUpdater.exe --force

8. 配置文件 gitupdater.ini

与 GitUpdater.exe 同目录，第一次保存设置时自动生成。除设置窗口里的项目外，还支持以下键：

节 / 键默认值说明
[General] Updateaskyes / ask / no
[General] UpdateOnceADayno每天只检查一次
[General] LogFilegitupdater.log日志路径，留空关闭日志
[Internet] SoftwareUrl空仓库地址
[Internet] AssetFile空资源文件名
[Internet] UserAgentGitUpdater/1.0GitHub API 请求的 User-Agent
[Internet] DownloadRetries2下载失败重试次数（总尝试次数 = 重试次数 + 1）
[Extract] StripRootFolderyes去掉单层根目录
[Extract] DeleteDownloadedFilesyes解压后删除压缩包
[Extract] BinPath空只提取压缩包内的指定路径
[Error] SupressInetReadnoyes 时静默网络错误

运行时还会写入 LastUpdateDate、LastUpdatedVersion、LastUpdatedRepo、LastReleaseUrl，用于版本比较。

9. 常见问题

提示“无法从 GitHub 获取 Release 信息”

检查网络、代理，以及仓库地址是否正确；日志中会记录 HTTP 状态码。GitHub API 匿名访问有频率限制，稍后重试即可。

提示“没有找到匹配的资源文件”

对照 Releases 页面核对文件名，注意 [$ver] 不含开头的 v、大小写与扩展名是否一致。

提示目标程序正在运行 / 文件只读

先关闭被更新的程序；只读文件需要去掉只读属性或以管理员身份运行。

更新后目录结构不对

调整“自动去掉压缩包的单层根目录”或“指定释放内容路径”，可先查看日志确认实际提取的源目录。

7z / rar 解压失败

安装 7-Zip（C:\Program Files\7-Zip\7z.exe），或改用 zip 资源。

日志在哪里

默认在 exe 同目录的 gitupdater.log，记录了每次执行的下载、解压、复制与清理过程。
