1. Quick start

  1. Put GitUpdater.exe into the folder of the application you want to update.
  2. Run GitUpdater.exe. The settings window appears on first run.
  3. Enter the GitHub repository and the asset file, then click OK.
  4. When a new version is found, a confirmation window appears. Click Yes to download and extract, No or close the window to skip the update.
  5. After the update finishes, the window shows “Update complete”. Click Close to exit.
GitUpdater only updates files; it never launches the updated application. Close the application before updating, otherwise files may be locked and the update fails.

The Help button in the lower-left corner opens this page in your default browser. The help pages are embedded in GitUpdater.exe (one Chinese, one English, chosen by the Windows UI language) and extracted to the system temp folder on first use, so no extra files appear in the program folder. A help_zh.html / help_en.html placed next to the exe takes precedence for that language.

3. Asset names and version placeholders

The asset file is not a regular expression and not a wildcard; only two placeholders are supported:

PlaceholderMeaningExample (latest tag v0.24.0-rc.1)
[$ver]tag without the leading vmarktext-win-x64-[$ver].zip → marktext-win-x64-0.24.0-rc.1.zip
[$tag]full tagmyapp-[$tag].zip → myapp-v0.24.0-rc.1.zip
If the real file name contains a v (e.g. TriliumNotes-v0.107.0-windows-x64.zip), write TriliumNotes-v[$ver]-windows-x64.zip; otherwise the resolved name lacks the v and never matches.

When no exact match exists:

  • The closest asset with the same extension is suggested and you are asked to confirm the download;
  • If nothing is close enough, all available assets are listed and the program exits with an error.

Both the confirmation and “already up to date” windows offer “Settings”: OK saves and re-checks immediately, Cancel returns to the previous window.

4. Extract path in archive (BinPath)

Enter a subfolder relative to the archive root, e.g. HydraPortable/App/Hydra, to extract only that folder's contents.

  • Both / and \ work; leading and trailing slashes are ignored, so HydraPortable\App\Hydra\ equals HydraPortable/App/Hydra.
  • Matching is case-insensitive.
  • Empty means extract everything.
  • This is a path inside the archive, not a local disk path.
If the configured path is not found, the log records [WARN] Configured path not found in archive: ... (extracting all) and everything is extracted instead. Check whether the archive has an additional top-level folder (e.g. the real path is app-1.0/HydraPortable/App/Hydra); include that level in the setting.

5. Supported archive formats

FormatHandling
.zipExtracted with PowerShell Expand-Archive
.7z / .rarExtracted with 7-Zip; if 7-Zip is missing, Windows tar is tried, then the update fails
.tar / .tar.gz / .tgz / .tar.bz2 / .tbz2 / .tar.xz / .txzExtracted with the built-in Windows tar
Other formats (.exe, .msi, ...)Downloaded only: not extracted, not executed

Extraction uses the temporary folder <install folder>.gitupdater_tmp, removed afterwards. Old version folders (names like 156.0.8078) are cleaned up; the current version folder is kept.

6. Version check

Versions are not parsed semantically; only the latest tag string is compared with the last installed tag. Same tag means “already up to date”, a different tag triggers an update. The recorded tag is bound to the repository name, so switching repositories re-checks.

Use --force to ignore the same-tag check and download again.

7. Command line

ArgumentDescription

Located next to GitUpdater.exe and created when settings are saved for the first time. In addition to the settings window items, these keys are supported:

[Internet] DownloadRetries2Retries after a failed download (total attempts = retries + 1)

At runtime LastUpdateDate, LastUpdatedVersion, LastUpdatedRepo and LastReleaseUrl are written and used for version comparison.

9. FAQ

“Could not read release information from GitHub”

Check network, proxy and the repository URL; the log records the HTTP status. Anonymous GitHub API access is rate limited, so retry later.

“No release asset matched the configured file name”

Compare the name with the Releases page. Remember that [$ver] has no leading v, and check case and extension.

“is running” / read-only file

Close the application being updated first. For read-only files, clear the read-only attribute or run as administrator.

Wrong folder layout after updating

Adjust “Strip a single root folder” or “Extract path in archive”. Check the log to see which source folder was actually copied.

7z / rar extraction fails

Install 7-Zip (C:\Program Files\7-Zip\7z.exe) or use a zip asset instead.

Where is the log

By default gitupdater.log next to the exe; it records every download, extraction, copy and cleanup step.
